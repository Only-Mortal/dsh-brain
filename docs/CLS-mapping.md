# 互补学习系统（CLS）与本项目代码的对照

> 参考：McClelland, McNaughton & O'Reilly (1995), *Why there are complementary learning systems in the hippocampus and neocortex*.
> 对照对象：`newborn` 当前实现（M1 + 推理后端 + 监控台）。日期：2026-10-28。

## 一、理论的三条硬约束

1. **两套系统、两套时间尺度。** 海马体快速、稀疏、模式分离，一次就能记住「哪一天发生了什么」；新皮层慢、重叠、分布式，通过大量交错经历学出统计规律。
2. **为什么必须分开。** 单一网络用高学习率学新事，会发生灾难性干扰——新记忆覆盖旧知识；用低学习率则学不到具体经历。所以快的存具体、慢的存结构。
3. **靠重放连接。** 离线（睡眠）时海马体把经历重放给皮层，且重放要**交错**（新旧混着来），皮层才能在不遗忘的前提下提取共性。

## 二、逐项对照

| 理论组件 | 本项目对应 | 现状 | 差距 |
| --- | --- | --- | --- |
| 感官流 / 经历发生 | `events` 表（append-only，`process_state`） | 已实现，两阶段落盘，可重放 | 只是原文日志，没有「稀疏编码」 |
| 海马体：快速情景记忆 | `memories`（`memory_type=episodic`，`lifecycle_state=active`，带 `source_event_ids`） | 已实现：注意力≥0.55 立即写入，一条经历一条记录 | 没有模式分离（近似重复靠 exact 文本比对），没有情景衰减/清理 |
| 海马索引（模式补全） | `memory.retrieve()`（关键词 + 时间） | 只有 LIKE 与排序 | 没有向量/稀疏特征索引，无法「由部分线索想起整段」 |
| 新皮层：慢速结构化知识 | `memories`（`memory_type=semantic`）+ `states.trait / identity` | **基本空转**：语义记忆没有任何生产路径；trait/identity 从未被更新 | 缺巩固任务，等于「皮层还没开始学」 |
| 交错重放 | 无 | **完全缺失** | 没有后台巩固（README 标为 M4） |
| 慢学习率 / 变化上限 | `states` 有版本号，但无速率限制 | 只对 affective/cognitive 每事件立刻更新 | trait/identity 应只在巩固中、按上限变化 |
| 灾难性干扰防护 | exact 内容去重（`find_active_duplicate`） | 只挡完全相同的句子 | 语义相近但不同的事件没有分类与聚类，未来做语义抽象时会互相覆盖 |
| 睡眠 / 离线期 | 无 | 缺失 | 需要独立的巩固模式（进程内定时或单独命令） |

## 三、最要紧的出入（按影响排序）

1. **只有海马，没有皮层。** 快速情景写入已经有了，但没有任何路径把 N 次经历压成一条结构化知识。系统的「性格」目前只由提示词和配置决定，不由经历长出来——这与 CLS 的核心主张相反。
2. **没有重放，也就没有交错。** 巩固若只取「最近 N 条」，等于把连续几天的同类经历连成一串喂进去，正好触发理论警告的干扰。必须随机/分层抽样，跨时间跨会话交错。
3. **情景记忆没有生命周期。** 现在 `active` 之后永远 `active`，只有 `access_count`。CLS 里海马痕迹是暂时的：该衰减、该归档，把长期价值交给语义层。
4. **模式分离缺位。** 两条「我今天很累」和「我今天有点累」是不同经历，却会被当成同一条（或都独立存下但无法区分重要性）。需要稀疏特征（shingle/Jaccard）+ 近似去重，而不是 exact 比对。
5. **状态层与经历层混用同一个更新通道。** 情绪每事件更新是对的（快），但 trait/identity 若也走这条路就会「一句话改变人格」。应限定：只有巩固任务能提案，且单次变化有上限、可回滚。

## 四、可落地的优化（建议顺序）

### P0-1 巩固任务（把皮层接上）——**已实现**（`consolidate.py`，2026-10-28）
新增 `consolidate.py`，作为独立命令 `python -m newborn.cli consolidate --hours 24 --seed 7`：
- 取时间窗内的 episodic，按「天 × 会话」分层抽样，各有上限；
- 指纹聚类（字符 3-gram 哈希 + 数字归一化，Jaccard ≥ 0.5）；
- 每个簇产 1 条 `semantic` 记忆：`structured_claim` 是真相源，`content` 只是 display_text；
- 簇保存 `cluster_id`（稳定概念身份）、`snapshot_fingerprint`（当前成员集合）、`version`；
- 语义记忆支持 strengthened / weakened / disputed 变化，旧版本 superseded 但不删除；
- 任务表 `consolidation_jobs` 以（窗口, seed, 算法版本）唯一，重复跑返回 duplicate_job。

### P0-2 交错重放预算——**已实现**
抽样按天分层，`per_day` / `per_conv` 双上限；产出前过 `check_sampling()`：覆盖天数、会话数、单层最大占比（阈值随层数放宽为 `max(0.55, 1/n+0.1)`）；分布与 seed 一起写进任务记录，同 seed 可完全复现（有单测）。

### P1-1 情景衰减与归档
给 episodic 加衰减：`importance *= exp(-Δt/τ_e)`，τ_e 默认 14 天；低于阈值转 `archived`，只保留来源与摘要。语义记忆不参与该衰减。

### P1-2 模式分离
写入 episodic 时计算 64 维 shingle 指纹（哈希投影）存进 `memories.features`；检索与去重都用指纹相似度，exact 比对降级为快路径。

### P1-3 trait 慢变化
`trait` 只接受巩固任务提案：单次 Δ≤0.05、每日累计≤0.1、保留旧版本（`states` 已有版本号，可直接扩展为历史行）。拒绝来自单条事件的直接写入。

### P2 检索双通道
海马通道：指纹/关键词精确命中；皮层通道：语义记忆的相似度排序。两路合并时给来源不同权重，并记录本轮「为什么想起它」。

## 五、怎么算做到了（验收）

- 巩固幂等：同时间窗跑两次，语义记忆数量不变，事件全被引用。
- 交错可证：巩固报告里能看到按天/按会话的抽样计数，且不是单峰分布。
- 无干扰：构造 20 条「今天很累」变体 + 5 条「今天很开心」，巩固后应产出 ≥2 条语义记忆且主题可区分。
- 情景会老：把时钟拨快 30 天，低价值 episodic 应转 `archived`，语义记忆不受影响。
- trait 有惯性：连续 50 条极端事件后，trait 单日变化仍在配置上限内。
